# ELEVATE SDE Internship - Task 3

Certificate issuing and verification backend API.

The project also includes a small browser portal for citizens and admins, plus interactive Swagger API documentation.

## Technology

- Backend: Node.js and Express
- Database: SQLite, accessed with `better-sqlite3`
- Admin password hashing: bcrypt
- Admin authentication: signed JWT bearer tokens

## Setup

Requires Node.js 20 or newer.

```powershell
npm install
Copy-Item .env.example .env
```

Set `ADMIN_USERNAME`, `ADMIN_PASSWORD`, and a random `JWT_SECRET` of at least 32 characters in `.env`, then start the server:

```powershell
npm start
```

The database file is created automatically at `DATABASE_PATH` (default: `./data/certificates.sqlite`). The configured admin is created or its password hash is updated at startup.

## API

| Method | Endpoint | Access |
| --- | --- | --- |
| `POST` | `/api/applications` | Public |
| `GET` | `/api/applications/track/:applicationId` | Public |
| `GET` | `/api/certificates/verify/:certificateId` | Public |
| `POST` | `/api/admin/login` | Public |
| `GET` | `/api/admin/applications` | Admin |
| `PATCH` | `/api/admin/applications/:applicationId/approve` | Admin |
| `PATCH` | `/api/admin/applications/:applicationId/reject` | Admin |
| `GET` | `/api/admin/certificates` | Admin |
| `GET` or `PATCH` | `/api/admin/certificates/:certificateId/revoke` | Admin |

Use the token returned by admin login as `Authorization: Bearer <token>` for protected routes. The optional rejection body is `{ "reason": "..." }`. Request and certificate IDs are generated by the API. Certificates begin with status `Valid`; revocation changes only the certificate, leaving its application status unchanged.

The revoke route supports the specified `GET` endpoint and a `PATCH` alternative for clients that prefer a state-changing HTTP method.

## Browser portal

After starting the server, open `http://localhost:3000` for the citizen forms (apply, track, verify) and admin console (sign in, review applications, approve/reject, list/revoke certificates). Admin sign-in uses `ADMIN_USERNAME` and `ADMIN_PASSWORD` from `.env`; there is no public account-registration flow.

Open `http://localhost:3000/api-docs` for the interactive Swagger UI, or `http://localhost:3000/api-docs.json` for the OpenAPI specification. The Swagger UI's **Authorize** control accepts the JWT from the admin login endpoint.

## Responses and validation

Applications start as `Pending`; approval and rejection are allowed only while pending. Re-approving/rejecting a completed application, or re-revoking a certificate, returns `409`. Unknown IDs return `404`. Required application fields are validated before saving. Public certificate verification returns the current certificate status, including `Revoked`.
